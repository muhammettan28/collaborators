# Mobile review — 2026-11-02

## How it was checked

- **Signed-in screens** in Chrome (signed in). Chrome would not make its window
  narrower than **606×844** this time (inner 606×701), which still gets the
  phone layout (below 768px). Below 606px, two more steps were simulated in
  the page: the window width the app reads was set to **390** and **360**, and
  the page narrowed to match. The only CSS rule for widths under 606px (the
  hierarchy note, under 500px) is not covered by this simulation.
- **Signed-out screens** (`/`, `/signin/`, `/workspaces/discover/?q=a`) in the
  Claude desktop app's built-in browser, at exact sizes **390×844** and
  **360×740**. It is not signed in.

Screens checked (signed in): dashboard `/`, Recent `/?target=all_docs`,
`/?target=notifications`, Search `/workspaces/discover/` and `?q=a`,
`/account/profile/`, a page opened from Recent ("Introduction"), the left
panel, the bell popup, and the "New" menu. Popups, menus and the panel were
closed afterwards; no settings or data were changed. Opening the page from
Recent updated its "last visited" time.

Branch: this review is on `collaborators/mobile-review-2026-11-02`, made from
`main` (`collaborators/phase-6` is already merged into `main` and 45 commits
behind it).

## What the script found

- **Sideways scrolling:** none, on any screen or size.
- **Sticking out:** only the known false alarms (hidden "Collaborators" label,
  drag handles of the closed panel, dnd-kit's live region). In the page, the
  table is wider than the screen but scrolls in its own frame.
- **Small tap targets, new this week:**
  - The presentation's slide buttons (first, back, play, forward, last),
    24×24, and the seconds-per-slide choice, 18px tall. **Fixed.**
  - "Presentation options" (20×20), a label's remove "×" (18×18) and
    "Add" label (19px tall), in the page header.
  - "See my profile" link on the profile, 20px tall.
- **Small tap targets, already known:** "Sidebar on the right" switch (34×18),
  "See all" (17px), "Add a card" (26px), the welcome card's close (26×26),
  card collapse and star buttons (28×28), Reading/Editing (26px tall), drag
  handles (22×26), header logo (29px). The footer legal links no longer show
  up: last week's fix is live.
- **Small text:** "MY" avatar initials (10px); the floating labels of form
  fields (11px, from the UI library), on the profile and the search field.

## Seen on screenshots

- At 360px the presentation's controls were 15px wider than the block, so the
  seconds-per-slide choice was cut off on the right. **Fixed:** it now goes to
  a second row (checked live with the same style).
- The page header (panel button, Reading/Editing, Shared, "…") fits at 390 and
  360: under 560px the Reading/Editing labels give way to icons.
- The bell popup (400px) shrinks to the screen and stays inside it.
- The New menu and the profile form (fields stacked) fit at 360.
- Search: the label cloud is indented under the heading, and when every label
  is used the same number of times they are all at the biggest size (27px,
  bold), so the cloud repeats the list below in very large type.
- Signed-out Search: `?q=a` does not fill the search field (signed in, it
  does).
- Signed-out home: the 3s fade-in is still there.
